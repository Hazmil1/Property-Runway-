# Deploy the full Property Runway app on free services

The sample at https://property-runway-demo.onrender.com/ stays separate.
Use `render.production.yaml` for the full app. It defines exactly one free web service, no paid cron, disk or database. The deployment has not been activated until the secure configuration below is complete.

## Required secure configuration
Use the existing separate Property Runway Supabase project `blkudvfjmmtfvowelzoj` in ProcureAI. Never use the Contract Runway database.
Enter values directly into Render Environment, not into GitHub source or chat:
- DATABASE_URL: Property Runway's Supabase Postgres connection string. Use the session pooler connection displayed by Supabase if the direct hostname is not reachable from Render. Percent-encode special characters in its password.
- SUPABASE_SERVICE_ROLE_KEY: Property Runway server-only secret/service-role key.
- NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY: this project's public configuration.
- BOOTSTRAP_OWNER_EMAIL: the intended first owner's exact work email.
- NEXT_PUBLIC_APP_URL: the full app's HTTPS URL, not the static sample demo.
- CRON_SECRET: generated by the Blueprint, at least 32 characters.

Configure Supabase Auth Site URL to the app URL and allow its /auth/confirm redirect. Test the sign-in email and use a production-capable SMTP configuration before onboarding users. First sign-in for the configured owner provisions the empty property-runway workspace; other people need invitations from its administrator.

## Database and storage preparation
The initial SQL schema has already been applied to the new project through Supabase. It currently has 19 empty application tables with RLS enabled and no client Data API policies: authenticated application requests use the server database connection and enforce organisation membership.
The startup script validates environment names (without printing secrets), takes a database preparation lock, checks schema drift, safely records the existing initial Prisma migration, applies any pending migrations, creates the empty workspace, creates a PRIVATE property-documents bucket and checks readiness before listening.
BASELINE_EXISTING_SCHEMA=true is needed only for this first existing-schema adoption. It refuses schema drift, absent row security or an ambiguous multi-migration history; it never resets data. Once the migration history is recorded, set the flag to false. Do not use db:push or the sample seed in production.
The seed command refuses NODE_ENV=production.

## Deploy
1. In Render's Blueprint setup, choose this repo and set Blueprint path to render.production.yaml.
2. Supply the required configuration above and confirm the sole web service is free.
3. Build uses npm ci and the committed lock; startup runs the preparation checks.
4. Confirm /api/health returns 200 with mode application.
5. Complete the acceptance checks below before adding real portfolio documents.

No local Render CLI is available in the authoring session. Blueprint fields were checked against Render's current documentation; validate the file in Render's Blueprint review before applying.

## Reminder scheduling without a paid Render cron
.github/workflows/notifications.yml runs daily at 07:17 UTC, but skips dispatch until BOTH the repository variable PROPERTY_RUNWAY_APP_URL and repository secret PROPERTY_RUNWAY_CRON_SECRET are set. The secret must match Render's CRON_SECRET.
This workflow creates due reminders; email delivery remains off unless RESEND_API_KEY and NOTIFICATION_FROM_EMAIL are both configured with a verified sender. Do not enable sending until recipient routing has been acceptance-tested.
GitHub schedules and free hosts are best-effort; they are not a guaranteed legal-deadline delivery service. Check the in-app dates regularly. Free service quotas and idle suspension still apply.

## Optional document extraction
AI_EXTRACTION_MODE=disabled is the default: documents can be stored and dates entered manually. Set webhook mode only with a real HTTPS provider and its secret, then verify extraction review. Mock extraction is refused in production.

## Acceptance
- Owner can sign in, then invite a second member and verify access roles.
- Create a freehold and leasehold; attach a tenancy, manager, break date and rent review.
- Verify property search and archived-property recovery.
- Upload and download a private document; signed downloads must expire.
- Confirm a member of a different organisation cannot read or change records.
- Verify legal date amendments and their audit entries.
- Dispatch reminders with sample recipients and inspect delivery/acknowledgement before enabling email.
- On a phone, use Menu to reach all pages and complete property/event forms.

## Remaining manual activation
Server credentials and owner identity cannot be retrieved safely through the available connector. Enter them directly in Render. Live authentication, storage and email acceptance tests remain pending until then.
